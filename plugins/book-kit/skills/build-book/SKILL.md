Build the HTML summary book end-to-end. First load the kit rules: invoke the `book-kit:rules` skill now unless its content is already in this conversation, and follow it strictly — the absolute rules above all. Run every script from the project root as `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/<name>.py" …`.

Arguments (may be empty): $ARGUMENTS

0. **Preflight.** If `book.config.json` is missing here, tell the user this directory is not a book project (run `/book-kit:init`) and stop. Run `scan_sources.py --status`.
   - `config.issues` mentions `content.level` → show it and stop. `sourceCount` is 0 → explain the expected layout (`sources/README.md`) and stop.
   - `office.refresh` is present → run `extract_office.py --all`, then scan again. A file it reports under `failed` could not be pre-extracted: tell its analyst so.
   - `state` is present → run `sync_state.py --sources`, say in one line what it remapped, renumbered or deleted, then scan again.
   - Show one line: sources to read / already extracted, level L (`config.level_name`), and — if any — the `unsupported` files with their hint (they are not part of the book). If the scan has `level.style_outdated` or `audit.other_levels`, say in one line each what they say. If the scan has `unread_visuals`, name those files and say what it says: their pictures cannot be read — export them to PDF if the pictures carry content. If `pdf_pages` says unknown, say that completeness of long PDFs cannot be checked until `pypdf` is installed.
1. **Extract.** For each entry of `extract`, delegate `book-kit:source-analyst` — one source per analyst, in parallel within the limit — and pass the entry as it is (`path`, `read`, `extraction`, `chapter`, `pages` or `slides`, `reason`). When all have finished, run `sync_state.py --stamp`. If it lists `problems`, route them once (rules: `extraction.*`) and stamp again; if problems remain, print them and stop. Keep what it prints under `reextracted` for the architect (the plan's unit references are already re-pointed by the script — say in one line what it reports). Skip the step when `extract` is empty and the scan shows no `stamp`.
2. **Plan.** Delegate `book-kit:book-architect` in full mode (the extraction directory, the existing plan if there is one, the analysts' gap notes, the `reextracted` entries if any). Skip the architect only when a plan already exists, step 1 read nothing, the scan shows no `replan` (a re-extraction the plan has not answered yet — pass its entries) and the arguments do not contain `--rewrite` — that is an interrupted build resuming. Then run `sync_state.py --plan`. On `problems`, route them once to the architect and run it again. If the architect reports `gaps_for_analyst`, route exactly those bounded gaps to `book-kit:source-analyst` (mode `fix`) once, run `sync_state.py --stamp`, and have the architect finalise. If problems remain, print them and stop.
3. **Write.** Take `write` from the output of `sync_state.py --plan`: for each chapter it lists, delegate `book-kit:chapter-writer` with that chapter's slice (`.book-state/plan/slices/ch-<id>.json`), in parallel within the limit. With `--rewrite` in the arguments, run `sync_state.py --plan --rewrite` instead: it lists every chapter in mode `full` (and the slices say so); the request stays on record until each chapter has been written again, so a later run without the flag finishes it. Chapters under `current` are not touched. Wait for all writers.
4. **Build & validate.** Run `build_book.py`, then `validate_book.py`. On FAIL, apply the repair routing from the rules once, then build and validate again. If it still fails, print the problems and stop (no audit on a broken build). On PASS with evidence warnings for a chapter written in step 3, give its writer the one pass the rules allow.
5. **Commit manifest.** `scan_sources.py --commit`. Its output gives `chapters`, `audit.next` (the audit number n), `audit.spot_checks_per_chapter` and — when an earlier report about this level is still open — `audit.prior`.
6. **Audit.** Delegate one `book-kit:book-auditor` per chapter (mode `chapter`, audit number n, level L, the chapter id, the spot-check budget) and one in mode `cross` (n, level L), in parallel within the limit. Where `audit.prior.parts` lists ids for a part (`ch-<id>`, `cross`), add the report path and those ids to that auditor's brief. When all have finished, run `sync_state.py --merge-audit --mode full --expect <every chapter id> cross`.
7. **Gate — REPORT → ASK → STOP.** Print what the merge printed: status, severity counts, the findings one line each, the report path, and where to open the book (`book/index.html`). If there are findings, ask exactly: "พบประเด็นตามรายการข้างต้น ต้องการให้แก้ไขหรือไม่? ถ้าต้องการ ให้พิมพ์คำสั่ง /book-kit:apply-fixes (การพิมพ์คำสั่งนี้คือการอนุมัติ 1 รอบ)" — then END YOUR TURN. Do not fix, do not re-audit, do not continue for any reason. With zero findings, say so briefly and point to `book/index.html`.
