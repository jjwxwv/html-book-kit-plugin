---
name: update-book
description: Incremental update — after source edits, new or removed sources, renumbered chapters, a new content.level or a config/design change. Redoes only what the scripts report as changed; validates; audits what was written; then stops at the approval gate.
disable-model-invocation: true
allowed-tools: Bash(python3 *) Bash(python *) Skill(book-kit:rules)
---

Update the book. Touch only what changed — and what changed is decided by the scripts, not by you. First load the kit rules: invoke the `book-kit:rules` skill now unless its content is already in this conversation, and follow it strictly. Run every script from the project root as `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/<name>.py" …`.

0. **Preflight.** If `book.config.json` is missing here, tell the user to run `/book-kit:init` and stop. Run `scan_sources.py --status`.
   - `config.issues` mentions `content.level` → show it and stop. `plan` is false → the book was never planned: tell the user to run `/book-kit:build-book` and stop.
   - `office.refresh` is present → run `extract_office.py --all`, then scan again.
   - `state` is present → run `sync_state.py --sources` and say in one line what it remapped (moved sources: no re-read), renumbered (the user renumbered source chapters: plan, drafts and links follow, no rewrite) or deleted (state of removed sources); then scan again.
   - Show one line: added / changed / removed / renamed, sources to read, level L, `unsupported` files if any; if the scan has `level.style_outdated` or `audit.other_levels`, say in one line each what they say; if it has `replan`, an earlier run stopped before the architect answered a re-extraction — step 2 runs with those entries; name `unread_visuals` files (pictures that cannot be read — export to PDF if they carry content), `unnumbered` files (in no numbered chapter folder; the architect places them by content) and an unknown `pdf_pages` the same way.
1. **Extract.** For each entry of `extract`, delegate `book-kit:source-analyst` (one source per analyst, in parallel within the limit; pass the entry as it is). Then run `sync_state.py --stamp`; route `problems` once, stamp again; if problems remain, print them and stop. Keep what it prints under `reextracted`. Skip when `extract` is empty and there is no `stamp`.
2. **Re-plan (delta)** — only when step 1 read something, step 0 deleted or renumbered something, or the scan shows `replan`. Delegate `book-kit:book-architect` in delta mode with: the extraction paths just written, the scan's `replan.extractions` if any, the `reextracted` entries (the script has already re-pointed the plan to the new unit numbers; the entries say which units were replaced in place, which are new, which are gone and which sections lost every unit — that is what the architect decides about, and it confirms the replaced ones with `reextracted_reviewed`), the sources that were removed, and what was renumbered or — `renumber_skipped` — could not be renumbered yet. It keeps the id of every surviving section, and takes a chapter whose sources are all gone out of the plan.
3. **What to write.** Run `sync_state.py --plan` — always: it checks the plan, refreshes the chapter slices for the current level and prints `write`. On `problems`, route them once to the architect and run it again; if problems remain, print them and stop. Say in one line what it reports under `renumbered_from_sources` (the book followed renumbered source folders), `chapters_sorted` or `drafts_retired` (drafts of chapters that left the plan, moved to `drafts/removed/`). A `plan.chapter_drift` warning that remains goes to the architect once with its text, then run `sync_state.py --plan` again. (After an interrupted run this is where unfinished re-planning shows up: `coverage.gap` names the new units and what they follow, `plan.section_emptied` the sections without units — pass those texts, and any `reextracted` this step prints, to the architect.)
   **`write` is empty** → nothing to write (a palette or template change, a setting no chapter depends on, a level that was written before, or an edit that changed no covered unit): run `build_book.py`, then `validate_book.py` (repair routing once on FAIL), run `scan_sources.py --commit` if step 0 showed any source difference, report that the book is up to date and what the build rewrote, offer `/book-kit:audit-book`, and stop — no audit, no gate.
4. **Write.** For each chapter in `write`, delegate `book-kit:chapter-writer` with that chapter's slice (`.book-state/plan/slices/ch-<id>.json`), in parallel within the limit. The slice says `full` or `delta`, which sections, and — under `form` — what the configuration no longer supports in the draft. Wait for all writers.
5. **Build & validate.** Run `build_book.py`, then `validate_book.py`. On FAIL apply the rules' repair routing once, then build and validate again; if it still fails, print the problems and stop. On PASS with evidence warnings for a chapter written in step 4, give its writer the one pass the rules allow.
6. **Commit manifest.** `scan_sources.py --commit` (gives `audit.next` = n, `audit.spot_checks_per_chapter` and, when an earlier report about this level is still open, `audit.prior`).
7. **Audit what was written.** Delegate one `book-kit:book-auditor` per chapter that step 4 wrote (mode `chapter`, n, level L, chapter id, spot-check budget) and one in mode `cross`, in parallel within the limit. Where `audit.prior.parts` lists ids for a part you audit, add the report path and those ids to that auditor's brief. Then run `sync_state.py --merge-audit --mode scope --expect <those chapter ids> cross` (`--mode full` when every chapter of the book was written).
8. **Gate — REPORT → ASK → STOP.** Same behaviour as `/book-kit:build-book` step 7: print the merged summary, the findings, the report path; ask the one question, naming `/book-kit:apply-fixes` as the way to approve; END YOUR TURN. Fixes start only when the user types that command.
